本報告一句話

過去，員工想外洩資料需要技術能力；今天，AI 已經把這個門檻拆掉了。

三大重點：

一、風險本質改變—— 過去資料外洩是 IT 部門的責任；現在每位員工都可能在無意間造成外洩。

二、技術防堵有極限—— 員工用個人手機、個人帳號就能繞過所有公司防火牆。

三、解法在管理而非技術—— 制度、教育、文化，比資安工具更關鍵。

SECTION 01　·　核心風險

三件最該擔心的事

用最白話的方式：公司有什麼可能會出事？出事會痛在哪裡？

01
極高風險
公司資料被發布到公開網站
員工用 AI 做出報表或查詢工具後，直接部署到公開網址（如 GitHub Pages、Vercel、Google 試算表共用連結）， 外部任何人都能存取，且 IT 完全不知情。
會痛在哪：客戶名單、財務數字、合約內容就掛在一個公開網址上，搜尋引擎可能索引，競爭對手可直接瀏覽。
02
極高風險
員工用個人帳號對外發布工具
員工用 AI 寫出一個小工具，用自己的 Gmail 發布到網路上，IT 完全看不見、也管不到。 員工離職後，工具仍然在運作。
會痛在哪：公司資料透過一個公開網址被外人看到，IT 在事發前後都不會知道。
03
高風險
無意識的洩密文化
員工普遍不知道「貼資料給 AI」等於把資料交給外部公司。 AI 寫程式的速度，遠遠超過員工資安意識的成長速度。
會痛在哪：不是惡意，而是無知造成的外洩，往往最難察覺、也最頻繁。
SECTION 02　·　ERP 開放寫入風險

開放寫入 ERP 的六大危機

當非專業人員可以直接透過 API 寫入 ERP，不只是 IT 問題，而是財務、法規、營運都會同步受衝擊。

01
極高風險
帳務混亂
非專業人員不熟悉會計科目與借貸邏輯，一筆寫錯可能讓整月帳軋不平。 ERP 資料一旦汙染，回頭清帳往往要耗費數倍人力。
會痛在哪：月結、年結無法如期完成；財報數字失真，影響決策與法遵。
02
極高風險
來源管控不易
多個系統或人員同時透過 API 寫入，難以判斷「這筆資料從哪來、誰授權的」。 追蹤異常時如同大海撈針。
會痛在哪：稽核查核時無從舉證，出現爭議也找不到明確責任人。
03
極高風險
繞過審批流程
畫面上的採購單、付款單需要主管簽核；API 直接寫入卻能跳過所有關卡， 讓一筆交易在無人審核的情況下直接成立。
會痛在哪：內控形同虛設，異常付款或偽造單據難以被攔截。
04
高風險
無法追責
若 API 金鑰共用、或未記錄完整操作日誌，出問題時只知道「資料被改了」， 卻不知道是誰在什麼時間做的。
會痛在哪：無法舉證、無人負責，問題反覆出現，內部信任也逐漸崩解。
05
高風險
資安事件後果放大
一旦 API 金鑰外洩（例如寫在程式碼或 Email 裡），攻擊者取得的不是「看」的權限， 而是可以直接改帳、刪資料、竄改主檔。
會痛在哪：供應商銀行帳號被竄改，付款轉入詐騙帳戶；損害立即且難逆。
06
中風險
系統穩定性下降
非專業人員寫的腳本可能在短時間內大量呼叫 API， 把 ERP 伺服器資源耗盡，影響全公司正常操作。
會痛在哪：業務尖峰時段系統變慢或當機，出貨、收款、對帳全部卡住。

五件最該做的事

抓重點，分先後。其餘技術細節，可由 IT 部門依此原則展開。
